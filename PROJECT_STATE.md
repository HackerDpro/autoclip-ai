## KNOWN PRODUCT LIMITATION (discovered via real test, important!)
Center-crop 9:16 strategy FAILS on specific source footage types:
  1. Videos with baked-in/hardcoded subtitles near the bottom of frame —
     these get cropped off since they weren't generated by us.
  2. Multi-person side-by-side horizontal layouts (e.g. two people sitting
     next to each other in a wide shot) — center crop just shows empty space
     between them, cutting off both faces.
This is a REAL, KNOWN limitation shared by every competitor (Opus Clip,
Submagic, etc. all struggle with this too) — not a bug, a genuine product
gap. Documented here as a real v2 differentiation opportunity: smart
content-aware cropping (face detection + active speaker tracking to decide
crop position dynamically) would be a legitimate competitive edge. NOT
required for Phase 0/MVP — simple center-crop is the correct, shippable v1.
Just need input-content guidance for users/testers: works best on single-
speaker, centered-subject footage (e.g. solo podcast/talking-head/webcam
style videos) until smart cropping is built.

## KNOWN GOTCHAS (don't repeat these mistakes)
- groq==0.11.0 is BROKEN (httpx incompatibility). Must use groq>=1.7.0.
- devcontainer.json changes require "Codespaces: Rebuild Container" command.
- Gemini free tier is unreliable (503 errors) — abandoned, do not revisit
  without strong reason.
- Groq free tier has an 8000 TPM limit on gpt-oss-120b — our retry-with-
  backoff logic already handles brief overages gracefully.
- Model names on Groq can be deprecated/renamed. Run src/list_groq_models.py
  to check current availability if hook_detector.py ever 404s. Update
  GROQ_LLM_MODEL in .env only, no code changes needed.
- Git push can fail silently-ish due to a broken Git LFS pre-push hook if
  git-lfs isn't installed. Fix: `rm .git/hooks/pre-push` (we don't use LFS).
- If a git push is rejected, check `git status` for diverged history before
  assuming the worst — "ahead by N commits" is fine, just push again in the
  actual terminal (not relying on VS Code's GUI panel log, which truncates
  real error messages).
